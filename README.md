# Векторный макет фактуры панельного дома для светильника (4 стороны, 165×320 мм, ЛМДФ)

Лазерная гравировка фасада типовой панельной многоэтажки по приложенному
образцу. Каждая сторона светильника — панель **ширина 165 мм × высота 320 мм**
(портретная ориентация). Генерация параметрическая, все размеры в миллиметрах
заданы в начале `scripts/generate_facade_v3.py`.

## Файлы

| Файл | Назначение |
|---|---|
| `output/facade_side1_165x320.dxf` … `facade_side4_165x320.dxf` | **Отдельные DXF на каждую из 4 сторон**, 165×320 мм, DXF R2010, единицы — мм |
| `output/facade_4sides_165x320.dxf` | Все 4 стороны на одном листе (раскладка 2×2, зазор 15 мм, лист 345×655 мм) |
| `output/facade_4sides_165x320.eps` | То же в EPS 3.0, координаты в мм, 8 RGB-цветов |
| `output/layout_colors.png` | Цветное превью листа 2×2 с подсветкой 8 классов объектов |
| `output/simulation_side.png` | Сторона 1: имитация гравировки лучом 0,2 мм на фоне ЛМДФ |
| `output/simulation_zoom.png` | Увеличенный фрагмент (окна, кладка, плитка, кондиционер) |
| `scripts/generate_facade_v3.py` | Генератор геометрии + технологический аудит + экспорт DXF/EPS |
| `scripts/render_simulation_v3.py` | Превью и симуляция луча из итоговых DXF |

Стороны собраны со своими seed (101, 202, 303, 404): расположение
кондиционеров, стиль створок, трещины и микро-дрожание линий воспроизводимы,
но у каждой стороны свои — на собранной коробке фасад выглядит как единое
здание с разных ракурсов.

## Состав стороны (снизу вверх)

1. **Цоколь на фундаменте** (0–20 мм): горизонтальные русты и две
   вентиляционные решётки с вертикальными прорезями.
2. **9 жилых этажей** по 29,33 мм (шаг ≈ 2,9 м в масштабе ~1:100).
3. **Техэтаж и плоская крыша** (284–320 мм): малые окна техэтажа с двойной
   рамой, три линии парапета, две вентшахты с крышками, у части сторон — антенна.

Слева направо 5 секций: одинарные окна → балконы → парные окна →
сплошное остекление → утопленные лоджии (на 1-м этаже — **подъезд** с
фрамугой, двустворчатой дверью, козырьком на упорах и двумя ступенями).

| Элемент | На макете | В натуре (≈) |
|---|---|---|
| Шаг этажа | 29,33 мм | 2,9 м |
| Окно парной секции | 13,2 × 15,5 мм | 1,32 × 1,55 м |
| Квадратная плитка стен | шаг 1,5 мм | 150 мм |
| Кирпич подоконного пояса | 4,0 × 1,7 мм | 250 × 65 мм |
| Кондиционер | 4,6 × 2,8 мм | 460 × 280 мм |
| Дверь подъезда | 12,5 × 19,5 мм | 1,25 × 1,95 м |

## Детализация по эталону

- **Две фактуры стен:** мелкая квадратная плитка (шаг 1,5 мм) по всему полю
  и кирпичные подоконные пояса ложковой перевязкой под парными окнами;
  обе текстуры автоматически клиппингуются по проёмам и водостокам.
- **Окна:** внешняя и внутренняя рамы, отдельные тонкие рамы каждой створки,
  форточки с собственным переплётом и ручкой, ручки створок, двойной отлив
  с капельником; четыре стиля раскладки (одно-, двух-, трёхстворчатые, со смещением).
- **Балконы:** верхний пояс из пяти мелких стекол, крупные нижние створки,
  плита под остеклением, парапет с филёнкой и вертикальной решёткой.
- **Инженерия:** водостоки из двух жил с воронкой, хомутами на каждом этаже
  и нижним выпуском; кондиционеры с вентилятором (кольца + лопатки), жалюзи,
  кронштейнами и гибкой подводкой; 2–3 диагональные трещины на сторону.
- **Естественность:** все векторы, кроме физической кромки панели, строятся
  с детерминированным микро-дрожанием (синусоида + случайная компонента),
  углы рам слегка «гуляют» — эффект ручной обводки.

## Технологические допуски (луч 0,2 мм)

- **Пересечения векторов разрешены** (T-стыки, кресты, примыкания швов).
- Аудит контролирует только параллельные векторы с перекрытием > 0,5 мм
  на расстоянии менее 0,25 мм — при пятне 0,2 мм такие борозды сливаются.
  Точное попарное расстояние между отрезками (алгоритм Эриксона) с
  пространственной индексацией. Результат по всем 4 сторонам:
  **0 параллельных слияний, 0 выходов за габарит 165×320**
  (~2 950 примитивов на сторону, 11 814 на листе).
- DXF проходит встроенный аудит `ezdxf` без ошибок; `$INSUNITS = 4` (мм).

### Экспериментальный импорт исходников

Текущая версия — **v0.4.0** (см. файл `VERSION`). Архив
`output/FasadPanel_VBA_import_v0.4.0.zip` содержит версию в имени и файле
`VERSION.txt`; `output/FasadPanel_VBA_import.zip` — копия последней сборки.
Номер версии отображается также в заголовке формы. При следующем выпуске
нужно увеличить `VERSION` и обновить номер в заголовке формы.

Архив содержит четыре стандартных модуля
и класс `clsFacadePreview.cls` в кодировке Windows-1251. Импортируйте класс
через File → Import File так же, как стандартные модули. В CorelDRAW создайте отдельный проект макросов
(не изменяйте работающий «шипоящик»), откройте его в редакторе VBA и через
File → Import File импортируйте все четыре `.bas`. Модуль `ThisMacroStorage`
импортировать не нужно: документный модуль создаётся самим CorelDRAW. В меню
Debug выберите Compile VBAProject и сохраните проект; затем попробуйте макрос
`modMain.FasadPanel`. Если появится ошибка компиляции, передайте её текст и
выделенную строку. На системе с другой системной ANSI-кодировкой кириллица
в импортированных файлах может отображаться неправильно.

Форма создаётся в редакторе VBA один раз: Insert → UserForm, имя `frmFasad`;
на ней нужно создать две кнопки с именами `btnOk` и `btnCancel` и вставить
код из `frmFasad-code.txt` в окно кода формы. Модуль `modFormRuntime` создаёт
остальные поля при открытии формы, не изменяя VBA-проект. Изменения v0.4.0
ещё не проверены в CorelDRAW; при неудаче предлагается пошаговый мастер.

Для обновления с v0.1.0, v0.2.0 или v0.3.0 сохраните резервную копию GMS. В редакторе VBA
замените все четыре стандартных модуля и класс `clsFacadePreview` файлами
из архива (удалите старые модули перед импортом), а код существующей
`frmFasad` полностью замените содержимым `frmFasad-code.txt`. Саму форму
и её кнопки `btnOk`, `btnCancel` оставьте. Выберите Debug → Compile
VBAProject и сохраните GMS. Пользовательские пресеты остаются в профиле Windows.
Один фасад строится от точки документа 0;0, четыре — от левого нижнего угла
активной страницы. Макрос не меняет размер страницы и не удаляет объекты. Перед
генерацией нужно открыть документ и проверить свободное место: существующие
объекты могут перекрываться. Отменить построение можно одной командой Ctrl+Z.
При построении в строке состояния отображается этап работы; не переключайте
документ до завершения. Скорость и совместимость в CorelDRAW требуют проверки. Для диагностики загрузки готового GMS
нужны результаты открытия новой сборки и текст возможной ошибки.

### Интерфейс и параметры

- постоянная UserForm создаётся один раз в редакторе VBA; её поля собираются
  при открытии, без изменения VBA-проекта. При ошибке доступен мастер InputBox;
- схематичный интерактивный предпросмотр и подсказки при наведении: условная
  схема не является итоговой геометрией или технологическим аудитом; для
  скорости изображается не более 20 этажей и 20 секций. Пропорции цоколя,
  крыши и типы секций показаны подробнее, но это не точная геометрия двигателя.
  Отдельный условный увеличенный фрагмент 20×20 мм показывает тип и размеры
  фактуры; при слишком мелком шаге его масштаб ограничен, поэтому он тоже не
  является точным отображением итоговых линий;
- номер секции выбирается из списка, для каждой секции отдельно выбираются
  её тип и наличие подъезда на самом нижнем этаже, включая цоколь. Изначально
  применяется автоматическая раскладка (подъезды в последних секциях); при
  явном выборе сохраняется конкретное расположение. Количество подъездов можно
  также изменить ползунком; это отменит ручное размещение и перераспределит
  подъезды по последним секциям. Под схемой указаны номера секций с подъездами;
- ползунки этажей, секций и высоты фундамента — 1–20 (для цоколя и числа
  подъездов — 0–20); размер фактуры A/B и шов — с шагом 0,1 мм до 20 мм.
  При изменении параметров шов и размеры согласуются автоматически: шов не
  меньше зазора луча + 0,2 мм и меньше A/B минимум на 0,1 мм. Ради этого
  ограничения зазор луча в форме ограничен 19,7 мм;
- опция четырёх сторон создаёт четыре отдельных сгруппированных варианта
  с соседними Seed, с промежутком 5 мм: в ряд, 2×2 или в колонку — первый
  подходящий вариант для текущего размера страницы. Если места недостаточно,
  построение не начинается. Занятые объекты не проверяются. При группировке
  CorelDRAW переносит объекты группы на один слой, сохраняя цвета линий.
  Для каждого фасада сначала создаются группы по цвету/классу, затем они
  объединяются в общую группу;
- вариант случайного рисунка (Seed) выбирается из списка или вводится своим
  целым числом от 1 до 2147483647; внутренние строки старых пресетов сохранены;
- независимые переключатели кондиционеров, балконов, труб и трещин;
- шесть встроенных шаблонов фасада, пользовательские именованные пресеты
  сохраняются в профиле Windows через VBA `SaveSetting` (в файле GMS их нет);
- 4 стандартных формы окон + случайный выбор стилей, балконный блок;
- 12 пресетов отделки и 8 типов фактуры: кирпич с перевязкой, горизонтальные
  и вертикальные доски, панели/плитка, каменные блоки, кирпич прямыми рядами,
  условные древесные волны и округлая галька. A/B задают размеры элементов;
  у волн используется только A, зазор учитывается для панелей и камня.
  Фактура строится в единой сетке на всей стене, а не отдельно в каждой
  секции и на каждом этаже; проёмы и трубы остаются препятствиями, а линии,
  слишком близкие параллельным границам, пропускаются ради зазора лазера.
  Контуры плит и камней у проёмов обрезаются, а не удаляются целиком.
  Превью показывает условный рисунок и изменения размеров, а не реальные линии;
  камень и волны — приближения, не точные копии образцов референса;
- пропорции фундамента, цоколя, крыши (плоская/двускатная/односкатная/нет),
  подъездов; панель 165×320 мм, зазоры и seed воспроизводимости.

### Сборка и проверка `.gms`

Формат Corel GMS = 18-байтный заголовок `GMS\x01…` + OLE/CFBF. Сборка
требует находящийся в корне репозитория `ShipoYaschik_V2_01.gms` как образец
служебных host-потоков. Успешная валидация не подтверждает работу в CorelDRAW:

```bash
python3 -m venv .venv
.venv/bin/pip install oletools olefile ezdxf matplotlib
(cd tools && npm install cfb@1.2.2)
.venv/bin/python tools/lint_vba.py        # статический контроль VBA
.venv/bin/python tools/build_gms.py       # cp1251, CRLF, MS-OVBA-сжатие -> build_streams/
node tools/cfb_wrap.js                    # OLE + GMS-заголовок -> output/FasadPanel.gms
.venv/bin/python tools/validate_gms.py    # round-trip 5 модулей и разбор oletools без warning'ов
```

## Рекомендации для производства

- При импорте в CAM проверить, что DXF не масштабируется: единицы миллиметры,
  габарит каждого side-файла 0…165 × 0…320.
- Сделать тестовый квадрат 50×50 мм на обрезке той же ЛМДФ и измерить
  фактическую ширину борозды; при отклонении от 0,2 мм изменить
  `PARALLEL_MIN` в скрипте и перегенерировать.
- Файлы в «прямом» виде — гравировка по лицевой стороне, зеркаление не нужно.
- Стороны нумеруются side1…side4; подъезд у всех одинаково расположен
  внизу справа — удобно для выравнивания углов коробки.
